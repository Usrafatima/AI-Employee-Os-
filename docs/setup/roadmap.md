# Two-week development roadmap

## Week 1 — foundations and core workflows

| Day | Focus | Outcome |
|---|---|---|
| 1 | Team onboarding, repository conventions, architecture review | Work ownership agreed; setup decisions recorded |
| 2 | Runtime bootstrapping, database migration baseline, authentication decision | Local environments can be assembled by each intern |
| 3 | Tenant/user/company foundation and shared UI shell | Authenticated workspace boundary established |
| 4 | CRM data flow and tasks | Customer/lead and task vertical slices defined/implemented by owners |
| 5 | Quotations and invoices | Commercial document lifecycle vertical slices integrated |

## Week 2 — integrations, intelligence, and hardening

| Day | Focus | Outcome |
|---|---|---|
| 6 | Documents, meetings, activities, notifications | Shared collaboration records connected |
| 7 | AI orchestration skeleton and one safe assistant path | Audited, approval-first AI boundary demonstrated |
| 8 | Email/WhatsApp/workflow integration boundaries and reports | Prototype modules connected or explicitly stubbed |
| 9 | End-to-end testing, authorization/tenant review, usability pass | Critical demo flows verified |
| 10 | Demo dataset, documentation, bug triage, release rehearsal | Demonstrable prototype and handoff notes |

## Priority order

1. Tenant-aware authentication and shared workspace layout.
2. CRM, tasks, quotations, invoices, and activity timeline.
3. Documents and meetings.
4. AI chat with read-only insights, auditing, and approval gates.
5. Communications, workflows, notifications, and reports as time allows.

For each module, define a single owner, reviewer, acceptance criteria, seed/demo scenario, and dependencies before implementation starts. Limit active work to small vertical slices and protect the final two days for integration.
